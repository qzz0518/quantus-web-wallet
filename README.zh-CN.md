# Quantus Web Wallet

[打开钱包](https://qtc.zezn.dev) · [English](README.md) | 简体中文

用于 Quantus 的网页钱包。

## 功能

- 创建、导入和管理多个 ML-DSA-65（官方钱包默认）和 ML-DSA-87 钱包及观察账户；导入时先显示派生地址，便于与官方钱包核对。
- 查询余额、发送 QTC、通过二维码收款、查看交易记录。
- 下载助记词，通过候选词选择验证备份。
- 快速在 Quantus 区块浏览器中查看账户与交易。
- 使用至少 6 位密码在本地加密钱包，支持加密备份导出与恢复。
- 在支持 WebAuthn PRF 的浏览器中，通过设备指纹、人脸或锁屏验证解锁。
- 发送前核对收款地址：疑似加密账户（Wormhole）地址会先提示后果并要求确认，没有链上记录的地址会给出提醒。
- 中英文界面，首次使用跟随浏览器语言，可在设置中切换。
- 支持浅色、深色及跟随系统主题，适配手机屏幕。
- 支持安装为 PWA，以独立窗口打开并离线启动。
- 支持只读查看虫洞地址。
- 加密账户（Wormhole）恢复：用官方钱包助记词扫描真实的未花费余额，并取回到普通账户（见下文）。

## 加密账户恢复

**是什么。** 官方 Quantus 钱包带有「加密账户」（Wormhole）。它的地址看起来和普通地址一样，但由助记词按 `m/44'/189189189'/0'/<branch>'/<index>'` 派生。每一笔转入这种地址的资产都会成为隐私池中的一条入账，只有持有助记词的人才能分辨哪些入账尚未花费——观察账户只能显示「未知」。不少用户误把资产转到了这类地址上。

**工具做什么。** 在 *设置 → 工具 → 加密账户恢复* 中，可以用官方钱包的助记词扫描加密账户。扫描是只读的：在一次性的本地组件中派生收款与找零地址，向官方索引服务查询这些地址的入账，在本地计算每条入账的花费凭证（nullifier），再向官方节点核对是否已花费。未花费的入账可以取回到普通账户：零知识证明在浏览器中生成，只提交一次。

**步骤。**

1. 打开 *设置 → 工具 → 加密账户恢复*，阅读说明。
2. 输入官方钱包的 24 个助记词单词。可选：粘贴官方钱包显示的加密账户地址，结果会告诉你它是否在派生地址之中。
3. 勾选网络查询提示后开始扫描。进度页显示阶段、分支、已扫描地址数和已找到的入账数，随时可以取消。
4. 查看结果：可取回余额、已花费入账、快照区块，以及可勾选的未花费入账列表。
5. 最多选择 7 条入账，选择收款账户（本钱包中的签名账户，或从同一助记词派生的普通账户），核对费用预览后提交。回执显示交易哈希、状态和区块浏览器链接；此前的回执会列在工具首页。

**费用。** 链上按取回金额收取 0.04% 的成交量费用。金额先向下取整到 0.01 QTC，每笔入账不足 0.01 QTC 的零头会丢失。费用一半销毁、一半归出块矿工，没有返还。生成证明需要约 1.5 GB 内存和一分钟左右，建议使用桌面浏览器。

**限制。** 扫描固定在节点与索引服务一致的某个最终确认区块，之后的入账不会包含在内。每个分支在连续 20 个未使用地址后停止；当账户超过每分支 1000 个地址或总计 10000 条入账时会拒绝给出余额，把不完整的扫描显示为错误而不是偏小的余额。一次取回最多 7 条入账，入账更多的账户需要分多次取回。助记词只留在页面与本地签名组件中，不会存储或上传；但官方索引服务与节点会看到派生出的地址和你的 IP 地址。

## 安装

打开[网页钱包](https://qtc.zezn.dev)，在浏览器中选择 **安装应用** 或 **添加到主屏幕**。iPhone 请使用 Safari → 分享 → 添加到主屏幕。余额更新与转账需要联网。

本地运行：

需要 [Bun](https://bun.sh) 1.4.0。也可通过 [mise](https://mise.jdx.dev) 运行 `mise install` 安装项目固定版本的工具。

```sh
git clone https://github.com/qzz0518/quantus-web-wallet.git
cd quantus-web-wallet
bun install --frozen-lockfile
bun run dev
```

打开 [http://127.0.0.1:5189](http://127.0.0.1:5189)。

构建并预览生产版本：

```sh
bun run build
bun run preview
```

将 `dist/` 部署到启用 HTTPS 的静态托管服务即可。`_headers` 文件包含内容安全策略和 HSTS，支持该文件的托管平台会自动应用。部署后运行 `node scripts/verify-deployment.mjs [站点地址]`，可校验线上每个文件与本地构建一致，并检查安全响应头。仓库已包含浏览器签名模块，仅在[重新编译该模块](vendor/PROVENANCE.md#rebuild)时需要 Rust。
